# C-009 · what MIB's filtering should do to the denominator

Written before the filter was run against the model, with only the dry-count (about 15,950 pairs per cell) and the selftest in hand. Configuration: `val`, 300 pairs built per cell, all three counterfactual types, all three targets, batch 48, 6 tokens, Llama-3.1-8B on NDIF, seed 0.

**1 · The clean base accuracy comes out ABOVE 0.69.** [T-020] reported unintervened accuracy of 0.6833–0.6917, and that number is not the model's own accuracy. It was measured through the patched path, where both arms carry an identical write, deliberately, so that a difference between the two columns is the intervention and not the decoding. `generate_clean` writes nothing. So the honest base-arm rate should be the higher of the two, and if it comes back at 0.69 on the nose that is evidence the layer-5 write was doing nothing to the base answer, which would itself be worth knowing.

**2 · The wikipedia counterfactual's source arm passes every single pair.** Not a prediction so much as a consequence of the code: its causal-model answer is the empty string, `check` asks whether any comma-separated part of the expected value is a substring of the output, and the empty string is a substring of everything. `source_ok` should equal `built` exactly, to the pair. If it does not, the port is wrong.

**3 · The joint keep rate sits near the product of the two arms, and well under either.** If the two arms were independent at roughly 0.7 each, the conjunction lands near 0.48. I expect somewhat above that rather than below, because both arms are the same model on the same kind of question and the easy cities are easy in both — correlated, so the conjunction beats the independent product. Call it 0.50–0.60 for `attribute_counterfactual` and `prompt_template_counterfactual`. For `wikipedia_counterfactual` it should equal the base arm alone, by prediction 2.

**4 · The balance step cuts the survivors to exactly `n_target + 2 * (n_target // 2)`,** composition target-attribute in full and each other attribute at half the target's count. The selftest already fixes this arithmetic; what is not known in advance is `n_target`, because the three attributes do not survive the correctness filter at the same rate. **If Continent survives much better than Language, the balanced set is larger when Continent is the target** — so the denominators of the three published numbers are not the same size, and that is a fact about the benchmark rather than about any method.

**What is affected if these come back otherwise.** Prediction 1 failing would mean [T-020]'s unintervened column needs re-reading. Prediction 2 failing would mean the port is wrong and nothing downstream is usable. Predictions 3 and 4 only size the denominator; they change what [T-018] has to match, not whether it can be attempted.
